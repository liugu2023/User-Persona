  先说硬件。主摄底大，进光量就大，夜景的可用性直接拉开档次：小底机器暗部糊成一片时，大底还能留住细节，这是物理层面的优势，后期救不回来。长焦的差距更直接，三倍和五倍不是数字问题，是构图自由度——五倍能把主体从杂乱背景里拉出来，三倍只能靠裁切，裁完画质就崩。

  最后说句实在话，旗舰的溢价有一半在参数之外——做工、手感、屏幕、系统顺畅度，这些不上参数表的东西，才是天天用手机的人能实实在在感知到的差距。

## T03 Linux 服务器部署实战：从零到上线
- 域 科技数码｜长度 L｜标签 programming 1.0 / devops 0.7｜特质 专业 1.0
- 审核：pending
- 摘要：Nginx 反向代理加 Docker 编排，一次讲完整条链路。
- 正文：很多人第一次把服务部署到线上，卡住的地方不是代码，是链路。链路不长，但每一步都有坑。

  从公网请求进来开始算：域名解析到服务器公网 IP，443 端口由 Nginx 接住，做完 TLS 卸载之后转发给内网的某个端口。这个端口后面是容器。容器怎么起、起几个、挂哪些卷、环境变量怎么注入，都由编排文件描述。从域名到端口、从代理到容器，三层之间任何一层配错，浏览器上看到的都是同一个「502」，这就是新手最容易崩溃的地方——错误信息不指向出错的位置。

  排查顺序建议固定下来，每次都从外往里查：先确认解析生效，再确认端口通，再确认反向代理转发地址正确，最后才看容器日志。反过来从容器开始查，往往会在业务代码里浪费很久，而问题其实在最外层。

  配置文件本身建议全部纳入版本管理，包括 Nginx 的站点配置与编排文件。服务器是会被重装的，重装那天你会庆幸自己这么做过。

## T05 Rust 入门：所有权模型在解决什么
- 域 科技数码｜长度 L｜标签 programming 1.0｜特质 深读 1.0
- 审核：pending
- 摘要：所有权模型在编译期到底解决什么，一篇讲透。
- 正文：学 Rust 的人往往先被所有权模型劝退，再被它救回来。想明白它在解决什么，比背规则有用得多。

  传统语言里，内存管理的责任是模糊的：程序员自己申请、自己释放，一不小心就是悬垂指针、双重释放、内存泄漏，这些问题只在运行期爆炸，排查成本极高。垃圾回收把责任交给运行时，代价是停顿开销和不可预测的延迟。所有权模型走的是第三条路——在编译期就把「谁拥有这块内存」说清楚。变量拥有它的数据，函数参数是借用还是转移所有权，编译器逐行检查，违反规则直接编译失败。

  代价是学习曲线陡。生命周期参数、借用检查器、可变与不可变借用的互斥，初看像枷锁，实则是把「内存安全」这份承诺从运行期提前到编译期——你损失的是写代码时的灵活，换来的是上线后少一类几乎无法定位的崩溃。

  这也是它适合系统编程、网络服务与嵌入式的原因：这类代码对性能和可靠性同样苛刻，编译期的严格换来运行期的放心，这笔账是划算的。

## T08 本地跑大模型：显存不够就用这个方案

- 摘要：显存不够跑不动？本地量化方案几步就能部署。
- 正文：本地跑模型卡在显存，最快的是量化：把权重从 16 位压到 8 位甚至 4 位，显存占用直接砍半再砍半，精度损失在多数日常任务上可接受。显存实在不够，就把模型拆分到多张卡，或走 CPU 与 GPU 混合推理，慢但能跑。别在本机硬等——7B 以下值得本地化，再大的模型直接调云端接口，更快也更省。这是当前本地与云端双轨并行的通用做法。

## T10 机械键盘选购：从轴体到配列

- 摘要：机械键盘从轴体到配列，每个选择都在决定手感。
- 正文：机械键盘的坑，不在价格，在选项太多。从轴体到配列，每层选择都在决定手感，说清楚再下单，避免买完后悔。

  轴体是灵魂。线性轴直上直下，适合打字快的人，长时间码字不累手；段落轴按下有脆响的确认感，喜欢「咔哒」反馈的人会着迷，办公室慎选，噪音是真实的社交成本。静音轴是折中，手感偏肉，换来安静。热插拔现在是标配，买错轴体不用重买整把，换几个轴就像换了把新键盘，这是整套键盘里最值得为未来付的溢价。

  配列层面，全尺寸适合离不开数字区的人，紧凑配列省桌面、双手距离近更舒服，但 F 区要按组合键。键帽材质决定长期体验：二色成型不褪字，涂层手感好但用久打油。铝壳的质感是塑料比不了的，键盘上的一份价钱一分货，在这里体现得最诚实，也是旗舰溢价最直观的所在。

  预算建议：轴体别省，外壳次之，键帽看喜好。下单前先租个试轴器上手按两天，比看一百篇评测都有用——手不会骗你。

## T11 我把家里的路由器换成了软路由
- 域 科技数码｜长度 L｜标签 hardware 0.7 / gadget 1.0｜特质 专业 1.0
- 审核：pending
- 摘要：折腾半年软路由，说结论：回不去了，但也别急着跟风。
- 正文：把家里路由器换成软路由，折腾了大半年，先说结论：回不去了，但也别急着跟风。

  软路由的实质，是用一台小主机跑路由系统，插件生态才是它的灵魂。去广告、分流、精细限速、内网穿透，这些在硬路由上要么没有、要么难配的功能，软路由都是装一个包的事。插件按需装、按需卸，系统本身开源免费，硬件花得省——一台二手小主机绰绰有余，功耗也就比家用路由器高几瓦。算下来一年的电费差距，几杯奶茶就打住了。

  代价是门槛。装系统要敲命令，排错要看日志，换插件全家断网十秒，家里人不一定理解，半夜断网的白眼得自己扛。最崩溃的一次是半夜升级，第二天全屋没网，顶着起床气重装系统。稳定的策略其实简单：装完冻结版本，只更新规则库，别手痒升级。

  值不值看需求：设备多、有共享需求、对网速敏感，值得；全家就一台手机刷短视频，原厂路由器够用，别给自己找事。
