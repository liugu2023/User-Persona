## 2. 关键决策记录（审核前必读）

1. **权重归一化 0.8→0.7、0.9→1.0（共 18 条）**
   《内容库设计.md》§3.2 规则三与 §9.2 precheck 明确规定权重只能是 0.4/0.7/1.0，但 §4.2 表格自身遗留了 0.8/0.9（如 T03 深读 0.8/专业 0.9）。按权威规则（precheck 会把 0.8/0.9 判为入库错误）归一化：0.8→0.7（明显相关）、0.9→1.0（就是在讲这个）。**配对表不受影响**——成对探针只看特质极是否存在，不看权重。md 与 JSON 已同步修改。

2. **探针缺陷修复（4 条）**
   sport（P11/P12）与 social（P13/P14）探针最初漏写 `traits` 字段（反序列化为 null），已补为 `{}`。设计 §5.1 要求探针**无特质**，修复后满足。

3. **共线性：速览↔大众等三对已修复（2026-09-03 复查全绿）**
   首轮发现速览↔大众 53%（设计 §4.2 原表继承）；新域加入后深读↔专业、大众↔速览两对一度升至 56.5%/61.1%。2026-09-03 处理：对正文调性为「实用指南/轻松向」而次要极名不副实的 7 条摘除该极——深读侧 E07（实验报告）、H07（排班表）、A08（综艺剪辑）、C03（影子跟读）；速览/大众侧 T09（十分钟搞懂大模型）、E04（整理笔记）、H12（群聊话题）。同时新增「专业+短文」反例 T13。现两对降至 45%/47%，**qa_check 已内置全库共线性检查，超标即红**。配对表成员（T03/L07/C05/A01/G04/S04 深读、T04/G10/L06/C06/S05/A09 速览）一律未动。

4. **敏感词复核：「定位」为误伤**
   共 2 处命中（T05「几乎无法定位的崩溃」= 程序 bug 定位；A04「声场打开、定位清晰」= 音频结像），均为正常语义，已从校验词表移除。运行时也只拦组合词（「实时定位」「GPS 定位」「你附近」），不使用单字 denylist。

5. **探针标题保守处理**
   §5.1 要求首屏探针"具体、低门槛、无阅读压力"，故标题基本沿用设计原稿（仅 P04/P05/P06 微调措辞），正文全部新写。若运营希望探针也带更强热点感，直接改标题即可，无副作用（探针为单标签、无特质，约束不受标题影响）。

6. **社交热点标签边界**
   原 `public_topic` 已改为 `campus_notice`（校园公共事务）。`social_hot` 只讨论校内通知、社团与日常公共资源，不延伸到校外时政或社会争议。

7. **首屏组按场次轮换**
   未指定组名时，`SessionStore` 依次使用 `default` / `campus` 两组探针；只有调试或复现实验才显式固定组名。

## 5. 人工审核清单（§9.3，放行前必做）

设计 §12.3 明确规定**审核不可外包给 LLM**。本批次已过机器检查，请按四条人工问题逐条通读 `01_~08_*.md`：

```
□ 这条内容如果出现在真实信息流里，看起来正常吗？
□ 它有没有可能冒犯某类人？
□ 它有没有暴露读者的健康、财务、身份、位置？
□ 它的调性和标签对得上吗？（标了"专业"的读起来专业吗）
```

四问全过 → 将对应分片中的 `review_status` 改为 `approved`，填写 `reviewed_by` / `reviewed_at`，再重跑 `merge_seed.ps1`；合并脚本会保留这些字段并同步到审核文档与聚合种子。
