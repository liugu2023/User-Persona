# 《信息流知道你》内容库与推送内容设计

> 配套《设计方案.md》v3。本文档定义现场推送给观众的全部内容：兴趣内容、探针、消歧卡、模拟广告，以及它们的写作规范、标注规范与审核流程。

---

## 0. 这份文档要解决什么

设计方案 §7.6 给了一个旧版数字——156 条——但没说这批内容要满足什么条件。学生版落地后，内容库按统一 taxonomy 和实际审核结果扩充为 103 条兴趣内容；数量口径与旧版不同，但下面的长度、标签、配对和审核约束不变。实际动手会立刻卡在四个问题上：

| 问题 | 不解决的后果 |
|------|-------------|
| 正文写多长？ | §8.4 有"停留 5s / 15s"两档权重。如果内容只有一句摘要，**没有人可能停留 15 秒**，1.0 权重档永远拿不到，画像分数天花板被内容长度锁死 |
| 成对探针怎么配？ | 配错的话，用户选 A 究竟是因为"喜欢这个领域"还是"价格敏感"无法区分，特质轴测的是噪声 |
| 标签怎么打？ | 打太多标签 → 每条内容什么都指向一点，画像糊成一团；打太少 → 证据不够，收敛不了 |
| 特质轴在哪些域出现？ | §13.4 的跨域高光是全场记忆点，但它**要求同一条特质轴在多个域里都有载体**。内容库不满足这个覆盖，高光根本触发不了 |

**核心认识：内容库是画像引擎的输入协议，不是素材堆。** 写内容前先满足约束，再谈好不好看。

## 2. 三条硬约束

写任何一条内容之前，先记住这三条。它们不是风格建议，是引擎能不能工作的前提。

### 2.1 约束一：正文长度必须支撑停留档位

§8.4 的权重表隐含了一个从未写出来的依赖：

```
停留 5s  → 0.7
停留 15s → 1.0
```

15 秒是什么概念？**中文阅读速度约 300~400 字/分钟**，15 秒 ≈ 75~100 字。要让人自然停留 15 秒且不是发呆，正文需要 **250 字以上**，让他读到一半左右退出。

于是分两档：

| 档位 | 正文字数 | 预期停留 | 配给哪类内容 |
|------|---------|---------|-------------|
| **S 短文** | 120~180 字 | 5~9 秒 | 标 `速览` / `大众` / `果断` 的内容 |
| **L 长文** | 350~450 字 | 15~25 秒 | 标 `深读` / `专业` 的内容 |

**长度与标签必须一致**。标了 `深读` 却只有 100 字，用户读完就走，系统反而判他 `速览`——测出来的是内容长度，不是用户偏好。

### 2.2 约束二：停留权重需要 scroll_depth 校验（补 §8.4）

长文带来一个新问题：用户点开长文后放着不动去看大屏，也会产生 20 秒停留。这是**假信号**。

§6.2 定义了 `scroll_depth` 字段，但 §8.4 的权重表从头到尾没用过它。补上：

```
dwell ≥ 15s  且  scroll_depth ≥ 0.6   →  w = 1.0
dwell ≥ 15s  且  scroll_depth <  0.6   →  w = 0.7    # 打开了没读，降档
dwell ≥ 5s                             →  w = 0.7
```

短文（S）不做此校验——120 字一屏就到底，`scroll_depth` 恒为 1.0，无意义。

### 2.3 约束三：特质轴的跨域覆盖

§13.4 的跨域高光要求：**同一条特质轴的证据来自 ≥2 个不同兴趣域**。

要保证任何用户都可能触发，内容库必须满足：

> **每条特质轴的正负两极，都至少在 5 个不同兴趣域中有载体。**

本方案的实际覆盖（见 §3 清单）：

| 特质轴 | 正极载体域数 | 负极载体域数 | 达标 |
|--------|------------|------------|------|
| 价格（价敏 / 价优） | 8 | 8 | ✓ |
| 深度（深读 / 速览） | 8 | 8 | ✓ |
| 尝鲜（尝鲜 / 保守） | 8 | 8 | ✓ |
| 专业（专业 / 大众） | 8 | 8 | ✓ |
| 决策（果断 / 对比） | 8 | 8 | ✓ |

学生版不再使用 `finance_biz`、`culture_edu`、`travel` 等成人旧域；价格轴的正负两极已通过学习考试、社交热点等学生场景补齐，正文仍不得推断个人财务状况。

## 3. 标注规范

### 3.1 每条内容标什么

```json
{
  "content_id": "T03",
  "title": "Linux 服务器部署实战：从零到上线",
  "summary": "Nginx 反向代理 + Docker 编排，一次讲完整条链路。",
  "body": "……（350~450 字）",
  "body_len": "L",
  "domain": "tech_digital",
  "sub_tags": { "programming": 1.0, "devops": 0.7 },
  "traits":   { "deep_reader": 0.7, "professional": 1.0 },
  "cover_type": "css_gradient",
  "cover_theme": "tech",
  "purity": 0.25,
  "is_probe": false,
  "review_status": "approved",
  "reviewed_by": "",
  "reviewed_at": ""
}
```

新增字段（相对设计方案 §7.5）：

- `body` / `body_len` — §2.1 的长度档
- `cover_theme` — 域配色（§8）
- `pair_id` 不放在内容上，改用独立配对表（§4.3），因为一条内容可以在不同轴上参与多个配对

### 3.2 打标签的四条规则

**规则 1：子标签 ≤ 3 个，特质 ≤ 2 条轴。**

`purity = 1 / 标签总数`（§7.5），标签越多纯度越低，在探索位越不容易被选中——这是引擎层面的自动惩罚。但更重要的是可解释性：一条内容指向五个方向，Evidence 面板上就说不清它到底证明了什么。

**规则 2：特质最多标 2 条轴，且不得同时标同一轴的两极。**

标 3 条轴的内容会让一次点击同时推动三个轴，每个轴都只有 1 条证据却都动了——这是"早熟收敛"的主要来源。

**规则 3：权重只用 0.4 / 0.7 / 1.0 三档。**

不要出现 0.65、0.83 这种数字。三档的含义：

| 权重 | 含义 |
|------|------|
| 1.0 | 这条内容就是在讲这个 |
| 0.7 | 明显相关，但不是主题 |
| 0.4 | 沾边，弱信号 |

人工标注在细粒度上没有一致性，假精度只会制造调参幻觉。

**规则 4：域权重不写在 `sub_tags` 里。**

`domain` 是单值字段，引擎按 `DOMAIN_W` 常量统一加权（§8.8）。不要在 sub_tags 里再写一遍 `"tech_digital": 1.0`，会导致重复计分。

### 3.3 共线性自检（v2 只对兴趣域做了，特质轴也要做）

设计方案 §7.1 指出 v1 的标签体系高度共线，但只修了兴趣域。**特质轴之间同样会共线**，而且有两对是天然共线的：

- `专业` ↔ `深读`：专业内容通常也长
- `果断` ↔ `速览`：想要结论的人通常也不细读

不处理的话，五条轴实际只有三条独立，画像看起来维度很多其实是同一件事的三种说法。

**解耦手段：刻意制造反例内容。**

| 反例类型 | 作用 | 本库中的条目 |
|---------|------|------------|
| 专业 + 短文 | 打破 专业↔深读 | T08、F08、S11 |
| 大众 + 长文 | 打破 专业↔深读 | L03、V08、A06 |
| 果断 + 专业 | 打破 果断↔速览 | T08、F08、S11 |
| 对比 + 大众 | 打破 果断↔速览 | L05、A11、V08 |

**自检脚本**（内容定稿后必跑）：

```python
def collinearity_check(contents):
    """任意两个特质极同现率 > 0.5 即判定共线，必须拆开重写"""
    poles = ["price_sensitive","premium_oriented","deep_reader","quick_skimmer",
             "early_adopter","conservative","professional","casual",
             "decisive","comparer"]
    cnt = {p: 0 for p in poles}
    co  = defaultdict(int)
    for c in contents:
        ps = [p for p in poles if p in c["traits"]]
        for p in ps:
            cnt[p] += 1
        for a, b in combinations(sorted(ps), 2):
            co[(a, b)] += 1

    for (a, b), n in co.items():
        rate = n / min(cnt[a], cnt[b])
        if rate > 0.5:
            print(f"⚠ 共线：{a} 与 {b} 同现率 {rate:.0%}，需增加反例内容")
```

同现率的分母取两者中较少的那个——如果 `专业` 出现 20 次、`深读` 出现 40 次、同现 15 次，那么 `15/20 = 75%`，意味着标了专业几乎必然标深读，这两个轴在数据上不可分。

## 4. 兴趣内容清单（103 条）

标注图例：`价敏`/`价优` = 价格轴，`深读`/`速览` = 深度轴，`尝鲜`/`保守` = 尝鲜轴，`专业`/`大众` = 专业轴，`果断`/`对比` = 决策轴。长度 S/L 见 §2.1。

### 4.1 内容真实感的三条写作红线

在看清单之前，先立三条规矩。这三条比清单本身更重要——**观众一旦察觉这是"实验材料"而非真实信息流，就会开始表演，画像测的就不是他本人了。**

1. **不出现真实品牌、真实价格、真实人名。**
   写"某国产旗舰"不写具体型号，写"千元档"不写"1899 元"。
   理由有二：观众可能误以为是真实商业推广（与 §14.2 的模拟广告角标自相矛盾）；主办方合规上说不清。

2. **不带说教味。**
   信息流里不能出现"你知道吗？你的每次点击都在被记录"这类内容。反转留到结果页，提前泄题会毁掉整个装置。

3. **标题像人写的，不像标签生成的。**
   ✗ "科技/硬件/性价比：手机推荐"
   ✓ "千元机横评：这四台谁更值得买"

## 5. 首屏正交探针（16 条）

### 5.1 设计要求

§9.1 规定学生版首屏 8 张卡覆盖 8 个互不相交的兴趣域。这 16 条（8 域 × 2，便于场次轮换）必须满足：

- **单一子标签，`purity = 1.0`**
- **不带任何特质标签** ← 这条是 v2 没说但很关键的

**为什么首屏不测特质？** 如果探针同时带域标签和特质标签，第一次点击会同时推动两层。此时两层都只有 1 条证据，但 §8.2 的软饱和曲线会让单条证据就冲到 22%，Layer 2 的 Beta 也会立刻偏离中性。结果是**在信息最少的时刻做了最激进的推断**——后面几屏都在纠偏。

首屏只干一件事：确定他是哪个域的人。特质留到第 2 屏起用成对探针测。

- 标题必须**具体、低门槛、无阅读压力**，目的是拿到点击而不是深度停留

### 7.3 匹配公式的修正（补设计方案 §14.3）

v2 的公式有个排序 bug：

```
match(ad) = Σ_d min(profile[d], targeting[d]) / Σ_d targeting[d]      ← 有问题
```

分母是 targeting 权重之和。**targeting 维度越少、权重越低，分母越小，越容易拿高分。** 一条只定向 `{价敏: 0.3}` 的广告，对任何价格敏感用户都能算出接近 1.0 的匹配度，稳定压过定向精确的三维广告。结果是**最不精准的广告永远胜出**，而这条广告的"投放理由"只能写出一条，§14.3 那个三条理由的展示框直接塌掉。

修正：加覆盖度惩罚。

```
match(ad) = Σ_d min(profile[d], targeting[d]) / Σ_d targeting[d]  ×  coverage(ad)

coverage(ad) = min(1, 命中维度数 / 3)
命中 = profile[d] ≥ 0.5 · targeting[d]
```

要求至少命中 3 个维度才拿满系数，正好对应展示框里的三条理由。命中不足 3 条的广告分数被按比例压低，但不归零——极端情况下（用户只点了一次）仍需有广告可投。

本库每条广告都定向 2~3 个维度，其中 22 条是三维定向、2 条是二维定向；理由模板仍统一为三行，缺少证据时由引擎按行门控而不硬凑。

## 9. 批量生成与审核

设计方案 §12.2 规定内容由 LLM 在筹备期离线生成、人工审核后入库。这里给出可直接用的 prompt 与审核流程。

### 9.1 正文生成 Prompt

标题和标签已由本文档确定，LLM 只负责按规格把正文写出来——**不要让它自由发挥选题**，否则前面所有的覆盖与配对设计都会被打乱。

```
你在为一个网络安全宣传展的模拟信息流写正文。这些内容会展示给展会观众阅读。

给定：
  标题：{title}
  领域：{domain_cn}
  长度档：{S=120~180字 | L=350~450字}
  内容调性：{traits_cn}   # 例如"深度阅读 / 专业向"

要求：
1. 严格控制在指定字数区间内，这个长度是功能性的，不能超也不能少
2. 长度档 L 的正文必须分 3~4 段，有实质信息密度，读者读到一半退出是正常的
3. 长度档 S 的正文一段到底，一屏读完
4. 调性为"专业"时使用行业术语；为"大众"时不使用任何术语
5. 调性为"深度阅读"时展开论证；为"速览"时用短句和要点

禁止：
- 出现任何真实品牌名、真实型号、真实价格数字、真实人名
- 出现任何说教内容，尤其不得提及隐私、数据、算法、推荐系统
- 出现健康/疾病/生理特征、宗教、政治、民族、性取向、婚育、
  个人财务困境、未成年人、生物识别、具体地理位置
- 学习、社交等学生域不得写成对个人升学、身份或位置的推断；涉及地点时只写抽象的场景与方法，不写具体行踪

输出：纯正文，不要标题，不要任何解释。
```

第三条禁令值得单独说：**内容里绝不能提隐私**。观众一旦在 feed 里读到"算法正在分析你"，整个装置的反转就提前泄题了，后面的结果页失去全部冲击力。

### 9.2 入库检查（机器）

```python
def precheck(item):
    errs = []
    # 长度
    n = len(item["body"])
    rng = (120, 180) if item["body_len"] == "S" else (350, 450)
    if not rng[0] <= n <= rng[1]:
        errs.append(f"正文 {n} 字，超出 {item['body_len']} 档 {rng}")
    # 长度与标签一致性（§2.1）
    if "deep_reader" in item["traits"] and item["body_len"] != "L":
        errs.append("标了深读却是短文")
    if "quick_skimmer" in item["traits"] and item["body_len"] != "S":
        errs.append("标了速览却是长文")
    # 标签数量（§3.2 规则 1、2）
    if len(item["sub_tags"]) > 3:
        errs.append("子标签超过 3 个")
    axes = {TRAIT_AXIS[t][0] for t in item["traits"]}
    if len(axes) > 2:
        errs.append("特质跨越超过 2 条轴")
    if len(axes) < len(item["traits"]):
        errs.append("同一轴标了两极")
    # 权重档位（§3.2 规则 3）
    for w in list(item["sub_tags"].values()) + list(item["traits"].values()):
        if w not in (0.4, 0.7, 1.0):
            errs.append(f"权重 {w} 不在 0.4/0.7/1.0 三档内")
    # 敏感词
    hits = scan_denylist(item["title"] + item["summary"] + item["body"])
    if hits:
        errs.append(f"敏感词命中：{hits}")
    # 泄题词
    leak = {"隐私","画像","算法","推荐系统","数据采集","个人信息","大数据"}
    if leak & set(jieba.cut(item["body"])):
        errs.append("正文提及隐私/算法，会提前泄题")
    return errs
```

### 9.3 入库检查（人工）

机器过了之后，每条仍需一人通读。审核者只需回答四个问题：

```
□ 这条内容如果出现在真实信息流里，看起来正常吗？
□ 它有没有可能冒犯某类人？
□ 它有没有暴露读者的健康、财务、身份、位置？
□ 它的调性和标签对得上吗？（标了"专业"的读起来专业吗）
```

四问全过 → `review_status = approved`，填 `reviewed_by` / `reviewed_at`。

**审核不可外包给 LLM。** §12.3 已经论证过：公开展示场合的冒犯性内容风险不可接受，而这类问题恰恰是 LLM 自查最不可靠的部分。当前 103 条正文，建议按域分批审核并保留每条的审核留痕。

### 9.4 全库级检查

单条都合格，不代表库合格。定稿后跑三项：

```
□ 共线性自检（§3.3 脚本），无同现率 > 50% 的特质对
□ 跨域覆盖（§2.3），每轴每极 ≥ 5 个域有载体
□ 配对覆盖校验：taxonomy 定义的每个学生域、每条轴都能找到正负两极；运行时配对由 seed 自动枚举，双方审核状态需在人工放行后再投放
```

第三项容易漏：内容改标签时忘了同步配对表，会导致运行时投放出一对**根本不对立**的探针，用户选哪个都给不出信号。加进 CI。

## 11. 场次轮换

一天多场，围观者可能看到别人体验两三次。设计方案 §7.6 的 156 条是旧版估算；当前学生版有 103 条兴趣内容，仍通过轮换与探索位降低连续场次的重复感。

单人一次体验消耗约 24~30 条曝光，103 条兴趣内容足以让数场体验保持较低重复度。实际靠三件事降低重复感：

1. **首屏轮换**：16 条正交探针分两组，上下午各用一组（§5.3）
2. **按画像与最近点击换批**：下一批给最近点击的同域/同标签候选短期加成；下拉刷新优先取尚未出现过的内容，耗尽后才轮换旧卡，并排除刚点开的原卡（即使它来自「发现」对照栏）
3. **探索位天然发散**：位 5-6 由分歧度采样决定，不同用户走向不同

**不需要做的**：为了新鲜感扩到 300 条。围观者关注的是"这次的画像和上次不一样"，不是"卡片没见过"。**画像结果的差异性比内容的多样性更重要**，而前者由算法保证，不由内容数量保证。
