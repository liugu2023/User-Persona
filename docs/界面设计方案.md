# 《信息流知道你》界面完善方案

> 范围：`demo/static/` 三个页面。**主任务是功能补全**——把点了只弹「演示版本」的死按钮换成真功能；UI 与适配一并做。
> 不含：内容库（`事件库/`，由内容审核流程独立维护）、画像引擎评分逻辑。
> 适配优先级：**用户侧（手机端）优先移动端；大屏与管理端优先电脑端。**

---

## 1. 死按钮清单与处理

清点结果：手机端共 5 处 affordance 点击后只弹「演示版本」toast，其余（首页、我的、结束卡、结果页全部按钮）都是真功能。

| # | affordance | 位置 | 处理 |
|---|-----------|------|------|
| 1 | 分类页签 ×8 | `mobile.js:155-161` | **删除**，只留「推荐」静态标签 |
| 2 | 顶栏搜索 | `mobile.js:160` | **改真功能**：「猜你想搜」联想词面板 |
| 3 | 顶栏铃铛（红点是假的） | `mobile.js:161` | **改真功能**：画像变更通知 |
| 4 | 底栏「发现」 | `mobile.js:294` | **改真功能**：不个性化的对照信息流 |
| 5 | 底栏「消息」（红点是假的） | `mobile.js:294` | **删除**，底栏变 3 格 |

贯穿这 5 项的约束：装置的核心主张是「它没问过你任何问题」，结果页 KPI 有一格「**0 字输入**」。下面每一项都不引入文本输入，也不让用户显式申报兴趣，这条 KPI 保持字面成立。

### 1.1 分类页签 → 删除

`buildTabs()` 去掉 `TABCATS` 数组与全部 onclick，`.tabs` 行只渲染一枚 `推荐` 选中态药丸，右侧补一行不可点的浅色提示「**为你生成 · 无需选择**」把这一行填满，避免孤零零一个药丸显得残缺。

保留首屏正交探针「不问就能猜中」的戏剧前提——如果用户能自己点「科技」页签，结果页揭晓时就变成「它当然知道，我点的科技」，反转的冲击力会塌。

### 1.2 搜索 → 「猜你想搜」

点搜索图标，从顶部下滑出一个面板：

- 顶部一个**只读、不可聚焦**的搜索框（不唤起键盘），显示占位符；
- 下方「猜你想搜」列出 5~8 个词，由 `/api/profile` 的 `domains` + `sub_tags` 的中文名实时生成；
- 词条**不可点**——它们是「它推断出的东西」的陈列，不是控件。面板底部一句：「这些词不是你搜的，是它根据你刚才的点击猜的。真实 App 里，它们会直接变成你的下一次推荐。」
- 一个「返回信息流」按钮关闭。

**零点击时**（画像为空）显示「还猜不出来 —— 你还没点过任何内容」。这本身就是一个很好的教学节拍，不是空状态兜底。

数据全部来自现有 `/api/profile`，无需改服务端。

### 1.3 铃铛 → 画像变更通知

红点变成真的。前端维护一份变更日志，每 5 秒轮询 `/api/profile` 与上一次快照比对，产生三类通知：

| 触发 | 文案 |
|------|------|
| top1 兴趣域发生切换 | 「它把你的首要兴趣改成了「游戏动漫」」 |
| 某条特质轴脱离中性区 | 「它现在认为你偏向「价格敏感」」 |
| 某个域的置信度达到满档 | 「「科技数码」的证据够了，它不再标注"证据不足"」 |

未读时铃铛红点亮起；点开列出条目（含相对时间「12 秒前」）并标记已读。面板底部一句：「真实 App 也在后台持续更新你的画像，只是从不给你发这条通知。」

复用 1.2 的面板组件。轮询直接用现有 `/api/profile`，无需改服务端；若现场发现该接口偏重（它会顺带算广告匹配），再加一个轻量参数，届时再说。

### 1.4 「发现」→ 不个性化的对照信息流

「发现」= 一份**完全不按画像排序**的固定列表，所有人看到的顺序一样。这正好对应《个人信息保护法》第二十四条「应同时提供不针对个人特征的选项」——装置自己示范了一遍合规做法，结果页的行动建议第 1 条可以直接回指。

要点：

- 服务端加 `GET /api/discover`（约 10 行）：从内容库取固定切片，**不读会话状态、不标记 seen、不推进屏序**；
- 限 8 条，无限滚动关闭，底部给一个回首页的入口，避免分流掉 90 秒；
- 「发现」页打开时 `MORE_IO` 暂停（照 `#mine` 现有做法），不推进首页屏数与收敛判定；
- **在「发现」里的点击照常计入画像**——这是刻意的。个保法二十四条管的是"推荐"，不是"记录"。结果页因此可以补一句非常锋利的话：「你在「发现」里点的 2 条，一样进了侧写。关闭个性化推荐，关掉的是**推荐**，不是**记录**。」

内容 ID 与首页同源，事件上报走现有通道，引擎无需改动。

### 1.5 推荐刷新 → 最近点击反馈 + 下拉刷新

首页的下一批内容不再只看累计画像。观众打开一张卡后，服务端把这张卡作为
短期推荐锚点：下一屏至少保留一个同域或同标签候选，其余位置继续按画像与
探索位分配。这样能呈现真实 App 常见的反馈回路，同时不会因为一次误点把
整条信息流锁死。

首页滚动到顶部后向下拖动，松手超过阈值触发「换一批」：

- 点击事件先 flush，再请求 `GET /api/screen?mode=refresh`，避免使用旧画像；锚点带会话内点击序号，多个请求乱序返回时仍以最新点击为准；
- 刷新批次插到当前信息流顶部，不推进体验屏序，也不改变结束条件；
- 优先使用尚未出现过的内容，素材耗尽后才轮换较早批次；
- 请求失败沿用整页状态的「重试刷新」出口，手势指示器不会卡住。
- 无触控设备在频道行提供同一请求链的「换一批」按钮；首屏加载失败时该入口退化为重试首屏。

## 2. UI 与适配

### 2.1 手机端（优先移动端）

移动端本身的正确性优先，桌面只做到「不难看」，不做完整桌面版：

- **触控目标**：`.tabs b`（现约 30px）、`.nav .ib`（34px）提到 44px；
- **安全区**：`#cardq` 顶部补 `--safe-t`（现在是 34px 平值，刘海屏上首行会被挡）；
- **横屏**：`orientation:landscape and (max-height:520px)` 单独一档，`#gate` 标题 `clamp(56px,17.5vw,78px)` 与结果页 hero 降档，否则一屏放不下；
- **大屏兜底**：`≥720px` 时给内容加 `max-width:460px` 居中壳层 + 两侧墨色留白，仅此而已——保证转发到笔记本打开时不是一条横跨全屏的信息流；
- **卡片版式**：信息流现在只有一种模板（`mobile.js:169-181`），连刷 6 屏 36 条全同构。按 `body_len` + `content_id` 哈希**稳定**派生三种版式（左图右文 / 大图卡用于 L 档 / 无图纯文用于短讯，比例约 5:2:3）。首屏探针强制统一版式——首屏是正交探针，版式差异会引入额外点击偏好干扰；
- **结果页导航**：10 个 `.blk`、6~8 屏高，现在只能盲滚。加顶部 2px 进度条 + 四段吸顶锚点（侧写 / 证据 / 反转 / 行动）；
- **页面级状态**：把「会话已过期」（2 小时 TTL，必然发生）、「连接中断」、「内容加载失败」、「结果生成失败」四种从 toast 升级为整页状态，各配一个出口按钮。

### 2.2 大屏（优先电脑端）

现在全是固定 px（`padding:34px 40px`、字号 21~104px 写死、三栏 `1.05fr 1fr 0.92fr`、跨域高光三卡合计 1100px），只在 1920×1080 成立。

- 以 1920×1080 为基准做优化，同时引入基准单位 `--u: clamp(9px, 1.05vh, 20px)`，字号/间距/圆角全部以 `--u` 表达——大屏可读性取决于**视距与屏高**，绑 `vh` 而不是 `vw`；
- 覆盖 1366×768 → 4K 不溢出、不出横向滚动条；
- 跨域高光三卡改 `repeat(3,minmax(0,1fr))`，卡内标题 `clamp()`；
- 竖屏立牌屏不作为目标，但加一条 `aspect-ratio < 1` 的降级（单栏堆叠，只留代号 / 侧写 / 雷达图），避免完全不可用。

### 2.3 管理端（优先电脑端）

现在是 `max-width:640px` 的手机式单列。改为电脑端优先的双栏：

- 左栏：聚合看板（在场 / 已完成 / 平均点击 / 收敛率 / 删除率 / 认为准）+ 内容库与参数状态；
- 右栏：会话列表与焦点控制；
- 危险操作（一键重置、删会话）拆到独立分组并作视觉降权，保留二次确认；
- `≤720px` 时退回现有单列，手机上仍然可用。

### 2.4 设计系统（与上面合并执行）

现在只有颜色被 token 化，字号有 20 余个互不成比例的散值。补齐字号 `--fs-*`、间距 `--sp-*`、圆角 `--r-*`、阴影 `--sh-*`、时长 `--dur-*` 五组，并与 2.1~2.3 一起落地，避免继续产生新的散值。

### 2.5 可访问性

- `.tabs` 的 `<b>`、底栏的 `<div data-k>` 改成 `<button>`（现在键盘不可达、读屏读不出）；
- 覆盖层（`#gate` / `#cardq` / `#reader` / `#result` / 新增的搜索与通知面板）加 `aria-modal`，打开时焦点移入、关闭时还原；
- 加 `<noscript>`，说明本页需要 JavaScript 并给出现场引导员的替代路径。

## 4. 验收

| 项 | 方法 |
|----|------|
| 死按钮清零 | 全站搜索「演示版」应无结果；顶栏底栏每个可见控件点下去都有真实反馈 |
| 搜索面板 | 零点击时显示「还猜不出来」；点过 3 条后联想词与结果页 top 域/子标签一致 |
| 通知 | 制造一次 top1 域切换，确认红点亮起且条目文案正确 |
| 发现 | 两台设备打开「发现」顺序一致；在「发现」里的点击能在结果页证据链中查到 |
| 手机端 | 360 / 390 / 460 / 768 / 1024 六档走完整流程；横屏 844×390 单独走告知页与结果页 |
| 大屏 | 1366×768 / 1920×1080 / 2560×1440 / 3840×2160 四档无溢出，3m 外可读 |
| 管理端 | 1440px 桌面与 390px 手机各走一遍 |
| 可访问性 | 全流程仅用 Tab / Enter 走通；覆盖层打开后焦点不逃逸 |
| 无回归 | 燕大蓝配色、`prefers-reduced-motion`、告知页/消歧卡溢出保护保持；刷新失败可重试且不推进屏序 |

浏览器与真机实测由部署方按现场验收计划执行；本文件只定义验收口径。

## 5. 执行顺序

1. **第一步 · 功能补全**：删页签与「消息」→ 搜索面板 → 通知 → 发现（含 `/api/discover`）
2. **第二步 · token + 适配**：五组 token → 手机端移动端优先项 → 大屏电脑端 → 管理端电脑端
3. **第三步 · 呈现与状态**：卡片三版式 → 结果页锚点导航 → 四种页面级状态
4. **第四步 · 可访问性**：语义按钮 → 焦点管理 → `<noscript>`

每步可单独验收，不必一次全上。
