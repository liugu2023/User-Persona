# 《信息流知道你》开发方案

> 唯一依据：《策划案-提交版》。本方案完全按照策划案内容展开，不与任何历史"展会观众版"文档混用。
> 状态：开发设计稿 v1，对应策划案全部可落地章节。

---

## 0. 本方案的范围与原则

依据策划案，本装置是一个**网络安全宣传互动体验系统**：观众用自己的手机扫码（或访问公网链接）进入模拟信息流，正常点开、停留、划过若干内容；大屏同步展示画像"生长"过程；流程后半段播放信息茧房前传、隐私反转、行动建议，最后可一键删除数据并带走书签。

从策划案提取的**实现铁律**：

1. **数据最小化**：不采集任何身份信息（姓名/手机号/学号/微信 openid/设备指纹/IP/精确位置/任何账号标识），全程 HTTPS；单次会话 2 小时自动过期，跨重启仅保留固定白名单中的聚合数字。
2. **白盒可解释**：每条展示结论必须能下钻到产生它的原始行为（哪条内容、什么动作、贡献多少），打分规则全部公开、可复核，不使用任何黑箱模型。
3. **准确性边界**：置信度不足的结论不予展示；"猜错"是教育素材不是事故（呈现"算法可能误解你"的白盒原因）。
4. **内容红线**：任何内容不得可反向推断健康、宗教、政治、婚育、财务困境、未成年、生物识别、行踪轨迹等敏感维度；机器校验 + 人工四问双通道，审核不委托给自动化完成。
5. **传播与隐私并存**：公网部署天然支持远程体验与链接转发，但隐私承诺（匿名、加密、限时删除）不对线上访问降低。

```
┌─────────────┐     ┌──────────────────────────────────────┐
│ 手机端 Feed  │     │          公网云服务器（后端）           │
│ 任何网络可访问├────►│   HTTPS 入口 + 会话管理                │
└─────────────┘HTTPS│   ┌────────┐  ┌────────┐  ┌────────┐  │
┌─────────────┐     │   │画像引擎 │  │推荐投放 │  │证据链   │  │
│ 现场大屏      │◄────┤   └────────┘  └────────┘  └────────┘  │
│ （拉取画像）   │WS  │   Redis：会话/事件缓冲/画像状态         │
└─────────────┘     │   DB：内容库 + 仅聚合统计                │
┌─────────────┐     │   监控/限流/自动重启                     │
│ 管理后台/仿真  │◄───┤                                        │
└─────────────┘     └──────────────────────────────────────┘
```

### 1.1 部署形态（策划案 7.2 落地）

- **后端与内容库**部署在公网云服务器（轻量实例即可），域名固定，HTTPS 证书。
- 手机端**不需要连接任何现场专用网络**，观众用自己的 WiFi / 移动数据即可扫码或打开链接参与。
- 二维码与体验链接**提前印制**在立牌、海报、书签上，随转发长期有效。
- **现场大屏**通过公网访问同一服务拉取实时画像与高光；现场需具备基础外网。若现场无外网，退化方案：大屏只播预录演示视频，观众仍可远程体验（见 §13）。

## 3. 核心机制：两层画像

策划案 5.1 定义了画像由两层构成，本方案优先实现该结构。

### 3.1 第一层：兴趣域（8 个大类）

观众点开/停留某内容，所属兴趣域分数上升。八个兴趣域（策划案 4.1 明确定义）：

**科技数码、游戏动漫、生活消费、运动户外、影视娱乐、文化艺术、学习考试、社交热点**

> 注意：策划案将受众定为学生版。本方案**只**使用上述学生版 8 域，不使用任何"财经商业 / 旅行"等成人向旧域。

### 3.2 第二层：行为特质（5 条对立轴）

跨板块的行为模式由五个特质轴刻画，这是产生冲击、超出预期的部分（策划案 5.2）。五轴与两极完全照录策划案：

| 轴 | 一端 | 另一端 |
|----|------|--------|
| 价格取向 | 价格敏感 | 品质优先 |
| 阅读深度 | 深度阅读 | 快速浏览 |
| 尝鲜程度 | 乐于尝鲜 | 偏好稳妥 |
| 专业程度 | 专业向 | 大众向 |
| 决策方式 | 决策果断 | 反复对比 |

### 3.3 呈现原则（策划案 5.2 / 4.5 强制）

**展示文案一律使用行为观察句式**（"当前浏览行为显示，你更关注价格相关信息"），**不使用人格判定句式**（"你是价格敏感型的人"）。这是科学边界，也是现场被质疑"凭什么几个点击就定义我"时的第一道防线。

另外按策划案 4.5，每条结论均标注"**基于本次浏览的判断**"，结论区底部固定一行：**算法看到的是行为，不是完整的你**。

## 4. 行为事件与计分

### 4.1 行为事件类型

策划案采集"点击 / 停留 / 滑动事件"（6.2）。本方案定义事件：`session_start`、`content_impression`（曝光）、`content_click`（点击）、`content_dwell`（停留，含总时长与滚动深度）、`content_skip`（快速划过）、`content_review`（返回查看）、`feed_refresh`（下拉换批，不计为新屏）、`probe_choice`（消歧二选一）、`profile_feedback`（「准/不准」）、`session_end`、`data_delete`（一键删除）。

### 4.2 行为权重（策划案 5.3 原文照录）

| 行为 | 权重 |
|------|------|
| 点击 | +0.5 |
| 停留 5 秒 | +0.7 |
| 停留 15 秒以上 | +1.0（**需通过滚动深度校验**，防止"开着页面发呆"刷分） |
| 快速划过 | −0.15 |
| 返回查看 | +0.4 |
| 消歧二选一 | +1.5 |

约束（策划案 5.3）：
- **同一内容不重复计分**，杜绝"反复戳同一张卡刷分"；
- 停留 15 秒的 +1.0 需滚动深度校验（停留在详情页且滚动到正文下方才计满档，否则降档甚至不计）；短文不做此校验；
- 分数经**位置修正与饱和归一化**折算为 0~100%。

### 4.3 计分与归一化

- **位置修正**：同一屏不同位次被点击概率不同，靠后位置被点击代表更强的真实兴趣，计算时按位次加权（位次靠后权重略高）。
- **饱和归一化**：原始分数累计后经饱和函数压到 0~100%，使"5 个强一致信号"即可冲到 90%+ 的高分，既有冲击力又单调、诚实、可解释，不做假归一化；避免任何"只点 1 次就逼近 100%"的虚高（那是毁掉可信度）。
- **特质轴**：五轴是**比例**而非总量，用证据的正反对比得出"明显偏向哪一极"。中间区间（无明显偏向）**不展示**，宁缺毋滥。

### 4.4 置信度与展示门槛（策划案 5.4）

- `conf` 由该结论的证据条数决定，证据不足时标注"证据不足"。
- 置信度不足的结论**不予展示**——宁可少说一条，不可说错一条。

## 5. 画像收敛策略

### 5.1 冷启动：首屏正交探针

第一屏覆盖 8 个兴趣域（每题一条、互不相交、不带明显特质引导）。第一次点击即可砍掉大量假设空间。首屏域组合按学生受众预置，后台可切换。

### 5.2 后续投放

信息流排序融合"兴趣位 + 探索位"（策划案"默认展示、探索"的平衡）：
- 已曝光内容不重复出现；
- 补齐证据不足的维度、拉开相邻维度区分度；
- 探索位置投放**该轴对立的两条内容**（如"专业向深度文" vs "大众向速览"），观众选哪条即给出该轴强信号——注意二选一必须**同域**，避免同时受域偏好干扰。
- 最近一次点击作为短期推荐上下文：下一批至少保留一个同域或同标签候选，
  其余位置仍按累计画像与探索位分配；下拉刷新只换批、不推进屏序。点击序号随
  推荐请求传递，正文预取或并发请求乱序时不允许旧锚点覆盖新点击。

### 5.3 强制收敛兜底：消歧二选一

若浏览约 40~60 秒后仍未收敛（策划案 4.1 步骤 6 之后），用一个"帮它确认一下"式的二选一澄清卡补足——取当前最纠结特质轴的一对对立探针，权重 +1.5 / 未选项 −0.5。**至多不超过 2 张**，保证任何观众都能拿到有内容的结果页。

> 消歧卡的叙事外壳应维持"帮它确认一下"的求助框架，避免读起来像考试题（策划案 4.3 示例的跨界故事即用自然语言）。

### 5.4 边缘用户兜底

| 情况 | 处理 |
|------|------|
| 全程零点击 | 结果页展示"你什么都没点，但我们仍知道你划过了什么"——用曝光/划过数据，本身就是另一种震撼 |
| 只点一次 / 乱点 | 展示有限、标注证据不足，然后补消歧卡；不强行给出高置信人格 |
| 已点每个域 | 判为"广谱好奇"，重心放特质轴 |
| 超时 | 自动结算进入结果页 |

## 6. 证据链（画像解释系统）

策划案 4.1(6) 与 5.4 要求：每条展示的结论都附证据链（内容标题、行为类型、贡献占比），不达到可追溯的结论不展示。

### 6.1 设计要点

- 结论区 / 大屏上的每个维度都可一键下钻到**具体是哪几次行为**得出的（内容标题、动作类型、贡献多少）。
- **跨域证据**：特质维度的证据必须标注来源兴趣域——跨域正是说服力所在（"你在游戏点开《平价外设推荐》+ 在学习停留《二手教材攻略》+ 在生活划过《网红餐厅打卡》，指向同一件事：这次浏览里你更关注价格"）。
- 只展示贡献最大的前几条，不全部罗列。

### 6.2 可解释的硬性要求

打分规则整体白盒公开、可复核（策划案 5.4）。任何展示给观众的结论，若下钻后无法解释，则不展示。

## 7. 教学环节（结果页之后）

### 7.1 信息茧房前传（约 10~15 秒，策划案 4.4）

并排展示"开场首屏"（八板块均衡分布）与"按当前画像继续投放十屏后"的模拟信息流——视角逐步从均衡收窄为单一板块相似内容。落点提问："这是更懂你，还是限制了你？"

**实现**：复用同一内容库按画像重排即可生成，不新增内容量（策划案明确）。开启本环节后才切入后续教学段。

### 7.2 隐私反转（约 15~20 秒，策划案 4.5 / 6.2）

逐项展示"我们从没问过你的信息"：姓名、手机号、学号、位置、任何一个字。并说明真实互联网中推荐系统可能综合用户主动提供的信息、授权使用的数据、公开可获得的信息。收束于"算法的局限"：即使综合再多的信息，画像仍是行为侧写，不是你本人。

### 7.3 「它可能看错你」：算法的局限（策划案 4.5）

在结果页与反转中落实三个触点：
1. 结论旁的固定提示（"基于本次浏览的判断"）+ 底部一行"算法看到的是行为，不是完整的你"；
2. 可展开的"为什么可能看错"三条白盒理由：**数据稀疏**（只看到 90 秒）、**行为不等于意图**（看优惠不等于价格敏感）、**没有上下文**（不清楚心情与场景，也可能在替室友刷）；
3. 反转收束句："数据画像不是你本人，只是算法眼中的你"，对照"刚刚你随时可以点「不准」、可以一键删除——真实的平台没有这两个按钮"。

### 7.4 行动建议（约 20 秒，策划案 4.1(9) / 6.3）

给出手机上可直接完成的三类操作路径：
1. 拒绝个性化推荐（个保法第二十四条：设置→隐私→关闭个性化推荐）；
2. 行使删除权（清理浏览历史/搜索记录；在本装置上当场一键删除）；
3. 权限最小化（通讯录/位置/相册"用完即关"）。

**行动建议是唯一"对策"落点，官方一票否决项（策划案 8.1）——只制造焦虑而记不住对策即失败，单独分配约 20 秒。** 书签承载"行动建议 + 关键法律依据"，法律全文可扫码在线上页面查阅。

### 7.5 一键删除我的数据（策划案 4.1(10) / 6.2）

结果页"立即删除我的数据"按钮，点击即时清空该观众全部记录，让观众亲身行使一次删除权。

## 8. 大屏系统（策划案 4.2）

### 8.1 三个状态

| 状态 | 内容 |
|------|------|
| **待机状态** | 轮播主标语与隐私承诺，提示扫码参与；可轮播累计聚合的"认为画像符合自己"比例（仅聚合数，无个体信息，策划案 4.5） |
| **实时画像状态** | 主区域展示当前焦点观众的画像生长（兴趣域进度条、特质轴、最近一次点击的计入结果）；侧边栏轮显其他在线观众（代号 + 最突出的兴趣） |
| **跨域推断高光** | 当某条结论的证据来自三个互不相关的板块时，大屏全屏播放动画，演示"三个不相关的动作指向同一件事" |

### 8.2 焦点切换（策划案 4.2 三级）

| 级别 | 规则 |
|------|------|
| 默认 | 定时轮换 |
| 高光 | 有人进入结果页或触发跨域推断时自动锁定约 10 秒，结束自动回落 |
| 人工 | 讲解员一键锁定（讲解时用） |

### 8.3 跨域推断高光（全装置记忆点）

示例（策划案 4.3）：

> 你在**游戏**板块点开《平价外设推荐》，
> 在**学习**板块停留阅读《二手教材交易攻略》，
> 在**生活**板块划过《网红餐厅打卡合集》。
> 三个不相关的板块，指向同一件事：**这次浏览中，你更关注价格。**

实现要点：证据需来自 ≥3 个互不相关的板块才触发；播放时长**以证据可读为准**（三张证据卡），全屏动画 + 手机端震动/抬头提示联动（当事人低头看手机时也能被提醒看大屏）。

### 8.4 可视化注意

- 进度条**长度**表示分数、**实心/虚线**区分置信度（证据不足标"证据不足"），避免"虚高但没证据"的观感；
- 分数是单调、可解释的成长，不是瞬时跳变；采用缓动动画而不是弹跳。

## 9. 内容库设计与内容安全（策划案 6.1）

### 9.1 内容构成与规模

全部为**预置离线内容**（非真实平台数据、不实时生成），总量按策划案 6.1：

| 用途 | 数量 |
|------|------|
| 常规兴趣内容 | 103（各域 12~14 条，含学生版扩充条目） |
| 首屏测试内容（正交探针） | 16 |
| 二选一澄清卡 | 10 组 / 20 个选项 |
| 模拟广告 | 24 |

> 96 条常规内容是旧版设计基线；当前学生版扩充为 103 条，以补齐跨域证据、示例标题和反共线性反例。消歧卡以 10 组记录存储、共 20 个选项。所有内容仍为预置离线素材，每域至少 12 条，降低同场重复感。

### 9.2 覆盖 8 个学生兴趣域（策划案 4.1 域表）

内容库按下列八域组织（域 = 覆盖主题封面）：科技数码、游戏动漫、生活消费、运动户外、影视娱乐、文化艺术、学习考试、社交热点。

- 每条内容须标注：所属兴趣域、长度档位、是否触发某条特质轴及其极性（或不带特质）；
- 五特质轴 × 八域 的区分度需要在内容设计时对齐（同轴要有正例与反例：既要有"专业向深度长文"，也要有"专业向短平快"，避免特质轴在部分域天然稀薄）；
- "生活消费/学习考试"域要刻意喂足"价格取向"证据（二手教材、平价网课等），作为跨域"更关注价格"推断的素材。

### 9.3 内容红线（硬约束，策划案 6.1）

内容中**永不出现**可推断以下信息的话题：健康与医疗、宗教、政治、婚育状况、财务状况、未成年相关、生物识别、行踪轨迹。

配套约束：
- 内容不得诱导或反向推断上述维度（例如"考公上岸经验""慢性病食谱"这类会暴露职业规划/健康状况的写法禁用）；
- 展示文案一律行为观察句式，不出现人格定论句。

### 9.4 审核流程（策划案 6.1）

内容上线执行**机器校验 + 人工审核**双通道，**审核不委托给自动化工具完成**：

1. 机器校验：关键词黑名单自动过筛（含红线维度关键词）；
2. 人工逐条回答四问，全部通过方可启用：
   - 出现在真实信息流里是否正常？
   - 是否可能冒犯某类人？
   - 是否暴露读者敏感信息？
   - 调性与标签是否相符？
3. 审核留痕（审核人、审核时间），内容可追责。

## 10. 数据采集边界与隐私实现（策划案 6.2）

开发实现必须把下表逐条变成代码约束（不是"建议"，是工程红线）：

| 承诺 | 实现方式 |
|------|----------|
| 只采集：随机会话代号、本页面点击/停留/滑动事件、「准/不准」反馈、由其计算的画像分数 | 事件 Schema 只含匿名会话 + 内容 ID + 行为类型 + 时间戳；无任何身份字段 |
| 不采集：姓名、手机号、学号、微信 openid、设备指纹、IP、精确位置、任何账号标识 | 前端不取、后端不记；HTTP 层不写访问日志里的 IP 到业务库；不使用第三方统计 SDK |
| 全程 HTTPS | 公网入口强制 TLS；非 HTTPS 请求拒绝或升级 |
| 会话数据仅内存运行、2 小时自动过期 | `SessionStore` 会话/画像只在内存；过期即销毁 |
| 仅聚合统计落盘 | `AggregateMetricsStore` 以同目录临时文件 + `os.replace` 原子写入 JSON，只存参与人数、完成/删除/过期数、准/不准数、匿名点击/刷新总量等数字，不存个体 |
| 即时删除 | "立即删除我的数据"直接删除该会话全部键 |
| 无公网泄露画像 | 结果页为本地生成的分享图（canvas 本地绘制），图片本身不含身份信息 |

### 10.1 大屏展示边界（策划案 6.2 已修订口径）

- 大屏只显示**随机代号**，与真人身份无关联；
- 告知页提供「不上大屏」开关（默认展示、可一键关闭），**「不上大屏」为全面关闭**：关闭后该观众同时从侧边栏兴趣列表与跨域高光动画中排除，不出现任何画像内容，仅保留代号展示（或不显示）；
- 观众随时退出，数据同秒清除。

### 10.2 分享与远程体验（策划案 6.2 已修订口径）

- 本装置部署于公网服务器，观众用自己的网络即可访问；体验链接本身可转发，支持**远程在线体验**；
- 结果页分享图在**本地生成**（不含任何身份信息），观众可转发至社交群组；
- 隐私承诺不因公网部署而降低：现场与远程访问采集的始终只有匿名行为事件，HTTPS 加密、2 小时自动删除、不采集身份信息。

### 10.3 告知与删除入口（策划案 4.1 步骤 2）

入口告知固定三句话：① 不需要姓名手机号；② 只分析本次点击行为；③ 体验结束自动删除。完整采集清单不堆在入口，体验中"我的"面板与结果页随时可查。

## 11. 管理后台与聚合统计（策划案 7.3 / 8）

### 11.1 管理后台（供技术值守、内容与合规观察岗使用）

- 参数微调面板：饱和度系数、收敛阈值、展示置信度门槛、每屏位次策略等（供开展前与现场值守使用）；
- 运行状态：在线人数、当前焦点观众、大屏连接状态、异常告警；
- 聚合看板：长期参与人数（含「不上大屏」）、完成数/率、匿名平均点击数、删除/过期率、结论「准/不准」认可率，以及当前在线收敛率。

长期统计口径：`accuracy_rate = feedback_accurate / (feedback_accurate + feedback_inaccurate)`，
没有反馈时返回 `null`；这里的“准确率”是观众对结果的认可率，不宣称行为画像有
客观真值。`/api/admin/reset` 只清当前内存会话，不清长期数字；主动删除和 TTL
自动过期分别计数，参与人数从创建会话时累计，是否上大屏不影响分母。

> 后台只读聚合统计，不提供任何个体会话下钻（下钻会违反 6.2 承诺）。个体级排障只允许在开发/仿真环境进行。

### 11.2 三层评估证据（策划案 8.1）

1. **首日试点深访**：邀请 10 名不知情学生完整体验 + 简短访谈，逐项记录达标线（"有点准 ≥7 人、能说出画像来自哪个行为 ≥8 人、有点意外 ≥5 人、记住行动建议 ≥6 人、主动分享 ≥2 人"）；
2. **装置内轻反馈**：结果页每条结论的「准/不准」（匿名、随会话 2h 过期）；
3. **匿名现场问卷**：两题（"结果准不准 / 你会不会去关个性化推荐"），经观众自有网络提交、仅保留聚合统计，不经也不依赖现场系统。

**验收纪律**："记住至少一条行动建议"是一票否决项（策划案 8.1）；"认为有点准"**不设否决线**，只作诊断参考。

## 12. 蒙特卡洛仿真校准（策划案 5.4 / 7.1）

### 12.1 为什么做

策划案 5.4 要求开展前进行 1000 次蒙特卡洛仿真校准；"开展前跑一次"不是软性动作，须写成 **D-7 前置验收**（策划案 7.1）。

### 12.2 校准方式

- **虚拟用户模型**按学生版 8 域构建 persona（主兴趣域 + 副兴趣域 + 特质倾向 + 点击率/停留档），另含三类边缘用户：乱点、只点一两次、全程不点；
- 仿真必须复用**线上同一套投放与计分代码**（首屏探针 → 兴趣/探索位 → 消歧卡兜底），否则校准结果在真实反馈回路下不成立；
- 每次 1000 次模拟、可反复迭代（几秒一轮），真人小样本只用于最后确认。

### 12.3 校准目标（策划案 7.1 倒排表口径）

| 指标 | 目标 |
|------|------|
| 常规观众判对率 | ≥ 80% |
| 收敛率 | ≥ 85% |

> 口径：仿真内部以虚拟用户为基准，是**工程验收指标**，仅供开发验收，不对外承诺。边缘用户（乱点/只点一两次/零点击）按设计不收敛是预期行为，走兜底文案（"沉默的观察者"），**分母为常规观众**。
> 现场对外只采用**体验认可度**（观众自评），不使用"准确率"一词（策划案 5.4 / 8.1）。

## 13. 容错与降级（策划案 7.4，按公网部署修订）

| 风险 | 预案 |
|------|------|
| 公网服务 / 现场外网异常 | 参与者体验不依赖现场网络（各自走自己的网络）；云服务器监控 + 自动重启；现场大屏断连自动重连，连续 30 秒失败切预录演示视频 |
| 公网入口被刷量 / 滥用 | 服务限流 + 基础验证防脚本刷量；无账号体系、纯匿名数据，单次会话影响有限；异常自动告警并临时收紧 |
| 后端故障 | 手机端自动进入降级模式（内置内容库），丢失大屏联动但不中断体验 |
| 设备全部异常 | 发放书签 + 备用平板一对一演示，宣传任务不中断 |
| 内容引发质疑 | 现场公示全部打分规则与证据链，由内容岗即时响应；质疑意见登记并纳入次日迭代 |
| 人流高峰 | 并发上限内正常体验，超出则新用户仍可体验但不上大屏（提示"当前排队中，你的画像仍在生成"）；单人体验 100 秒内结束，吞吐可控 |

## 14. 里程碑与技术选型

### 14.1 开发里程碑（对齐策划案 7.1 三阶段）

1. **能跑**：公网部署 + 多用户并发 + 大屏联动联调；
2. **能说服**：学生版内容库扩写与人工审核（每子标签配 2~3 条不同切入点，避免"固定剧本"观感）、画像仿真校准达标、信息茧房演示与隐私反转流程打磨；
3. **能扛住**：降级预案演练、物料印制（书签/海报/立牌）、志愿者培训。

### 14.2 倒排时间表（D 日 = 活动日，与策划案 7.1 一致）

| 时间 | 事项 |
|------|------|
| D-14 | 场地与用电批复；学生版内容库定稿 |
| D-7 | 全部内容人工审核放行；画像仿真校准达标（判对率 ≥ 80%、收敛率 ≥ 85%，以常规观众为分母） |
| D-3 | 全流程联调；降级预案逐项演练（断大屏 / 断后端 / 现场断网各一遍） |
| D-1 | 物料进场（含书签）；志愿者集中培训（半天），发放一页话术卡 |
| D-0 | 开场前 30 分钟设备巡检，各岗位就位 |
| D+3 | 聚合数据简报与试点访谈纪要归档，报送主办方 |

### 14.3 技术选型建议（满足"公网 + 匿名 + 可维护"）

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | Python FastAPI（或同轻量框架） | 单机轻量、开发快；现场零 LLM 实时调用 |
| 状态 | Redis（TTL=2h） | 会话/画像/事件缓冲；TTL 天然实现"2 小时自动过期" |
| 内容/聚合 | 内容库文件 + `AggregateMetricsStore` JSON（单文件） | 内容库 + 仅聚合统计；Demo 用原子替换写入，不存个体 |
| 部署 | 轻量云服务器 + Nginx + HTTPS（Let's Encrypt） | 域名固定、二维码提前印制；公网可远程访问 |
| 大屏 | 浏览器页面 + WebSocket | 从公网服务拉取实时画像与高光 |
| 手机端 | 移动端 H5（响应式） | 扫码即玩、无需安装 App；本地 canvas 生成分享图 |
| 队列/监控 | 进程内队列 + 简单告警 | 轻量可运维 |

**现场零 LLM 实时调用**（策划案内容预置离线 + 白盒计分的精神）：内容、文案、人格标签全部离线预生成并人工审核，热路径无第三方模型调用；不引入不可复现/不可解释的黑箱环节。
