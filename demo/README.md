# 《信息流知道你》Demo

《开发方案.md》的可运行 demo。零第三方依赖；会话/画像全在内存，仅匿名聚合
数字原子落盘，**断网可跑**。长期文件不含会话编号、随机代号、内容 ID、点击
明细或画像。

```bash
uv run demo/server.py                 # 默认 8000 端口
uv run demo/server.py --port 9000
```

启动后终端会打印本机局域网地址：

| 端 | 地址 | 用途 |
|----|------|------|
| 手机端 | `http://<本机IP>:8000/` | 观众扫码进入（二维码指向这个地址） |
| 大屏端 | `http://<本机IP>:8000/screen` | 现场大屏，SSE 实时刷新，断线自动重连 |
| 后台 | `http://<本机IP>:8000/admin` | 管理员登录后操作：锁定观众 / 切页 / 调 κ / 一键重置 |

参数校准（§8.9，开展前跑）：

```bash
uv run demo/simulate.py -n 1000        # 用当前参数跑一轮
uv run demo/simulate.py --sweep        # 扫 κ
```

后台首次启动会在终端打印本次进程的随机登录密钥；现场需要固定密钥时，启动前设置 `YUNA_ADMIN_PASSWORD`（也兼容 `ADMIN_PASSWORD`）。登录态使用内存会话和 HttpOnly Cookie，服务进程退出后自动失效。长期聚合统计默认写入 `demo/aggregate_metrics.json`，也可用 `YUNA_METRICS_PATH` 指定位置；离线 `simulate.py` 不传路径，不会写入现场统计。该 Demo 仍是 HTTP 局域网服务，正式部署应放在 HTTPS 反向代理后。

线上手机端结束时只显示结束卡并直接生成结果，不再弹出消歧提问；引擎里保留的旧版消歧接口仅供历史离线仿真兼容。

## 文件

| 文件 | 内容 |
|------|------|
| `engine.py` | 画像引擎、收敛策略、Evidence、投放、行为观察标签、广告匹配 |
| `server.py` | stdlib HTTP + SSE，全部路由 |
| `simulate.py` | 蒙特卡洛仿真与参数校准（§8.9） |
| `static/mobile.html` | 手机端：隐私告知 → 信息流（按最近点击换批、支持下拉刷新）→ 结束卡 → 结果页 → 隐私反转 → 删除 |
| `static/screen.html` | 大屏：待机轮播 / 实时画像 / 跨域推断高光 / 多用户侧栏 |
| `static/admin.html` | 引导员遥控 |

### 长期聚合统计

服务端在创建会话时累计全部参与人数，是否勾选「不上大屏」不影响计数。结果
成功生成、主动删除、TTL 自动过期和「准/不准」反馈也只更新匿名数字桶；进程
重启后从 JSON 恢复。文件白名单字段为：参与人数、完成数、主动删除数、自动
过期数、准/不准数、已收尾会话的点击/刷新总数及其分母。后台和大屏的
`accuracy_rate` 定义为「准」/（「准」+「不准」），无反馈时为 `null`；它表示
观众认可率，不宣称画像有客观真值。

管理员的「一键重置」只清当前内存会话，长期聚合数字故意保留；单个会话删除
同样不会回退参与人数或反馈历史。若需清理统计文件，应在服务器部署目录中
按运维流程删除/归档该匿名数字文件后再启动服务。

内容直接读 `../事件库/contents.seed.json`、`ads.seed.json` 与 `cards.seed.json`，不复制、不改写。

## 视觉与交互两条约定

**一套配色，取燕山大学校色。** 中性灰白 + 单一强调色「燕大蓝」（`--ysu:#1e4d99`），金色（`--gold:#c9a24a`）只用于「证据不足」这类提示态，红只留给「删除」一个危险动作。手机端所有页面——告知、信息流、正文、结果页——共用它，不做深浅切换；墨世界（深色底）的强调色自动切到亮一档的蓝（`--ysu-2:#4f8be0`）以保证可读，机制见 `mobile.css` 顶部的 `--ac` 注释。大屏和后台是同一套色的深色变体（藏青底 + 蓝 / 金强调，展厅深色环境下避免大面积浅色反光）。画布（星图、趋势、分享图）从 `:root` 读同一组变量，不另存一份色值。

**不靠滑动自动结束。** 滑到底只加载下一屏；画像收敛（且至少 3 屏）或到 6 屏上限后，在信息流末尾出一张结束卡，由观众主动点「查看结果」，旁边留一个「继续浏览」的回头路。早先版本是刷满 4 屏自动结算——不点也能几秒滑到底，体验戛然而止。

**推荐批次会跟随最近点击。** 每次打开内容后，事件先送达服务端；下一屏会在累计画像排序之外，给与最近内容同域或同标签的候选一个短期加成，并排除刚点开的原卡。首页顶部向下拖动并松手即可「换一批」，旁边也提供键盘/鼠标可用的「换一批」入口：刷新不推进体验屏序，优先取未出现过的内容，素材耗尽才轮换较早批次；即使最后一次点击来自「发现」栏，也不会立刻把同一篇塞回首页。点击序号会随锚点请求发送，网络乱序时仍以用户最新一次点击为准。

## 当前实现取舍

### 1. 首屏保持 8 域探针

学生版只使用 8 个兴趣域：科技数码、游戏动漫、生活消费、运动户外、影视娱乐、文化艺术、学习考试、社交热点。首屏按 §5.1 覆盖 8 域；如果某个域因为内容库不完整没有探针，后续屏位 3 会优先补投从未曝光过的域，避免推荐从第一屏开始自我强化。

### 2. 早期成对探索不锁死 top1

`_pick_pair()` 仍坚持同域 + 对立轴，但在 top1 证据未满前，会在 top1/top2/top3 与低置信域之间比较探索价值；top1 证据满后再收窄到 top1。这样可以降低第一次误点带来的滚雪球。

### 3. 证据按内容去重

同一内容的点击、停留、返回查看会合并成一条 Evidence，贡献累加，动作取最新一次。raw 分仍按增量更新，但前端不会把同一篇内容拆成多条证据，`n_evidence` 也不会虚高。

### 4. 结果口径保守

`persona()` 和 `summary_text()` 只描述本次浏览。主兴趣域证据不足时只显示「兴趣信号」或「信号有限」，不拼接具体特质；特质轴置信不足时不展示。

### 5. 广告匹配加域相关性因子

`match_ads()` 会把广告得分乘上画像在被定向域上的实际分数，避免「泛用特质」压过更精确的同域广告。结果页仍展示原因，但文案限定为模拟广告。

## 当前校准口径

默认 `κ=3.5`，让兴趣分数更克制。`simulate.py` 仍保留 §8.9 指标，但当前事件库还在编辑中，判对率和收敛率只作为算法回归参考，不作为内容质量结论。

## 现场降级（§8 三项技术原则）

| 故障 | 表现 |
|------|------|
| 大屏断连 | `EventSource` 自动重连，1.5 秒退避，不需要人管 |
| 后端断连 | 手机端事件队列原样保留并重试，服务端按 `seq` 幂等去重，不会重复计分 |
| 全部异常 | 引导员发折页——四条行动建议已经印在上面 |

没有任何外网依赖：封面是 CSS 渐变，字体用系统字体，分享图用 canvas 本地生成。
